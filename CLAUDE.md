# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev`: dev server at http://localhost:3000
- `npm run build`: static export into `out/`, with a TypeScript check along the way
- `npm run design`: regenerate the pages from `design/*.dc.html` (runs `python3 scripts/import_design.py`)
- Type-check only: `npx tsc --noEmit`

There are no tests and no linter. `npm run build` is the check that matters.

Node is installed through Homebrew but may not be on the shell's PATH. If `node` or `npm` isn't found, use `/opt/homebrew/Cellar/node/26.12.0/bin/node` (e.g. `node node_modules/next/dist/bin/next build`). `.claude/launch.json` (gitignored) starts the dev server for the browser preview.

## Architecture

A Next.js (App Router) portfolio for Aishat Muhammed, content marketer and community manager: six main pages plus case study pages under `/work/<organisation>/`. `next.config.ts` sets `output: "export"` and `trailingSlash: true`, so the site must stay fully static: no server actions, route handlers or dynamic server features.

**The design canvas is the source of truth.** Each page was designed as a design-canvas file, copied into `design/` (`Home`, `About`, `Work`, `TalkShelf`, `OpenTabs`, `Contact`, and one `Case<Name>` file per case study, e.g. `CaseSereel` for `/work/sereel/`). Each design file is listed in `PAGES` in the converter with its route; a new case study also needs its hand-written `app/work/<name>/page.tsx`. `scripts/import_design.py` converts each one into three generated files:

- `components/views/<Name>View.tsx`: the page markup as JSX. `{{holes}}` become `h.<name>`, `<sc-if>` becomes `{h.x && (...)}`, `X.dc.html#frag` links become `${BASE}/route/#frag`, `/_blob/<id>` images become `${BASE}/images/<file>` via `design/images.json`.
- `components/logic/<name>.js`: the page's `class Component extends DCLogic` script, copied unchanged. `renderVals()` returns every hole value and handler (theme toggle, mobile menu, scrollers, talk shelf selection and swipe, copy buttons, ripple cursor).
- `app/<route>/page.css` (`app/page.css` for Home): the page's `<helmet><style>` CSS with the font family and image paths adjusted.

Generated files start with a "Generated by scripts/import_design.py" comment. Don't edit them by hand: change the design file and re-run `npm run design`. If a change can't be expressed in the design file, change the converter. Hand-written files are `app/layout.tsx`, each `app/**/page.tsx` (route metadata plus `<XView />`), `app/icon.svg`, `lib/`, `next.config.ts`.

- **`lib/dc.js`** is a minimal `DCLogic` base class (`props`, `state`, `setState` that calls `_notify`).
- **`lib/useDC.ts`** instantiates a logic class once per page, re-renders on `setState`, and returns `renderVals()`. The first render is always light so server and client HTML match; a layout effect then applies the saved theme from `localStorage["aishah-theme"]`. On the server it sets `_themeBound = true`, which skips the browser-only setup inside `renderVals()`.
- **`lib/base.ts`** exports `BASE` from `NEXT_PUBLIC_BASE_PATH` (empty by default; `/Portfolio` for GitHub Pages project hosting). Every internal link and image path is prefixed with it.
- **Page openings** use cross-document view transitions: each page's CSS has `@view-transition { navigation: auto }` and draws the new page as a circle growing from `--vt-x`/`--vt-y`. A small inline script in `app/layout.tsx` remembers where a link was clicked (sessionStorage) and sets those variables in the next page's `pagereveal` event. Browsers without view transitions just load the page.
- Internal links are plain `<a>` tags, so moving between pages is a full page load. That keeps each page's CSS isolated (the pages share class names like `.home`, `.nav`, `.btn`), so don't switch them to `next/link` without scoping the CSS first.

## Styling

- Each page's CSS is self-contained, with tokens in three layers (primitive, semantic, component) on `.home`, and a dark theme on `.home[data-theme="dark"]`. `body` gets its background from `body:has(.home[data-theme="dark"])` in the same CSS.
- Fonts are self-hosted: `@fontsource-variable/figtree` (registered as "Figtree Variable"; the converter rewrites `Figtree,` to `"Figtree Variable",Figtree,`) and `@fontsource/ibm-plex-mono/500.css` for the small mono labels. Both are imported in `app/layout.tsx`.
- `.reveal` sections use a scroll-driven animation (`animation-timeline: view()`), so they look blank in full-page screenshots until scrolled into view.

## Content

- Text in `[square brackets]` is a placeholder the owner still needs to replace (mostly on the Work page and some talk shelf entries).
- Images live in `public/images/`. `design/images.json` maps canvas blob ids to file names; the converter exits with the missing id if a design uses an unmapped image.
- Never publish the owner's phone number.
